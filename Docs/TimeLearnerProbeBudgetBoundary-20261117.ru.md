# Остановка до изменения кандидата при исчерпанном бюджете проб

В длинном Classic опыте17 ноября native Train сохранил actual L=[51,1,1,1]
при последней завершённой измеренной точке L=[50,1,1,1]. Outcome честно равен
budget_exhausted, сертификата нет. Причина в NextAction: проверка maximumProbes
стояла после выбора и выдачи следующего Edit либо ResistanceDomain.

Проверка перенесена до формирования нового кандидата. При probes==maximumProbes
контроллер завершает управление без нового edit или оценки домена. Уже arm-нутые
и pending-действия сохраняют прежнюю семантику. Lifecycle Rdk, scheduler,
параметры модели, допуски и правила Exact не меняются. Это не автоматический
откат к глобальному best и не обещание полного измерения при обрыве процесса
либо исчерпании бюджета посреди anchor/input пары.

Регрессия в корневом Tests/Integration/Libraries/Test_PulseLib_BoundedTraining.cpp
проверяет production BoundedTrainingSession с ProbeRecorder для Classic/Branch,
N0/N1 и derived resistance-domain actions N1. После двух разрешённых наблюдений
остаётся последняя измеренная модель, новый domain/edit не выдаётся,
сохраняются budget_exhausted и отсутствие сертификата. Контролируемый отклик
проверяет решение контроллера, а не доказывает сходимость физического нейрона.

Адресная серверная проверка принята17 ноября на Elder: Root
0efbf25b074ca4dcf8439dde8160fa9e70697376 / PulseLib
5dabcb1b0c627d1de52bf2dccec35f33cb755e92. Изолированная сборка a2 выполнила86/86
выбранных native C++ случаев без skips/failures, включая boundary test и
production-reader cases. Первоначальная попытка a1 дала85/86 из-за неверного
ожидания теста: явно заданный initial-граф не требует preview-domain action.
В a2 исправлено ожидание; production код PulseLib не менялся.

Это приёмка конкретной границы решений контроллера, не экспериментальная
сходимость длинного физического нейрона и не покрытие всей обязательной матрицы.
Завершённая длинная пара и новый опыт с cap16 используют прежний неизменённый
runtime Pulse9883f949. Дефект и его ограничения сохраняются в интерпретации
этих данных. Перенос большой модели и native inline/file A/B идут отдельно.
