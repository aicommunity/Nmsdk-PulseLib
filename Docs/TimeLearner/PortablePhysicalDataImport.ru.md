# Перенос представлений DATA2 и DATA3 между компиляторами

Причина наблюдавшегося отказа прямого импорта — сравнение всего документа
с повторно построенным нативным документом, включая написания скалярных
типов в XML. Численный граф при этом мог совпадать. Изменение сравнения
в этой ветке является кандидатом исправления; серверная приёмка и прямой
перенос настоящих файлов между GCC и MSVC ещё требуются.

Сохраняется прежний путь: проверка исходного DATA-документа, нативный
импорт неизменного источника, воспроизведение явного преобразования либо
установки порога и проверка эффективного графа. При сравнении результата
`SamePortableModelArchive` проверяет исходные суммы обоих архивов и всех
снимков, их семантические описания и полные XML-деревья. Для имён типов
используется общий контракт Rdk `SamePortableSerialization`. Числа,
размерности, классы, связи, метаданные, порядок образов и зависимости
должны совпадать. Остальная часть DATA-документа сравнивается точно.

Сравнительные представления не сохраняются и не получают новых сумм.
Исходные документы остаются неизменными. Старые версии схем и хеши модели
не меняются; повторного масштабирования сопротивлений, переноса
сертификата, загрузки истории контроллера или нештатного lifecycle нет.
Неизвестные написания типов не считаются переносимыми по предположению.

Новые интеграционные случаи используют настоящие storage/Environment
и production import для обеих топологий и способов нормализации, DATA2,
DATA3 и DATA3 из DATA2 с другим написанием типов. Отдельно проверяются
заново подписанные противоречивые типы XML графа и образов, неверные суммы
архива и XML. Перестановка имён типов в fixture проверяет поведение
реального импортера, но не заменяет прямого чтения настоящих GCC/MSVC
экспортов и сравнения их полных физических реакций.
