# Cold7 capture: точная представимость исходного протокола

Source follow-up после `b9fe5b9773e232150bcb846a8991f5bf27c2b70a`, без runtime acceptance/Service activation. Root source review обнаружил разрыв: full protocol validation исключает invalid assignment/missing origin, но допускает другие корректные input IDs, stimulus IDs/order, origin из существующих stimuli и непустой pattern binding. Cold7 MakePlan объявляет canonical inputN/pulseN/origin pulse0 и вычисляет hash из model.initialIsi; прежний capture мог молча нормализовать допустимые различия.

После построения Configured declaration capture теперь требует `reconstructed.protocol == original.protocol` и точного совпадения каждого reconstructed input window (inputId/channel/begin/end/stimulusId). Отказ `candidate_window_initial_protocol_not_representable` означает ограничение представимости cold7, а не запрет именованных low-level native протоколов. Ни новый alias, ни схема, ни изменение математического target не вводятся. Protocol/routing/source/selection/window policy не разрешается нормализовать. Run и очищаемые search initialModelRevision/epoch проверяются отдельно от protocol: их штатный declaration reset остаётся допустимым.

Шесть новых data controls сначала доказывают успешную `ValidateVerificationProtocol`, затем требуют точный representability refusal для renamed input, renamed stimulus, согласованной valid stimulus permutation, другого существующего origin и другого pattern hash. Positive control сохраняет protocol/windows при run/checkpoint reset. Предыдущий WrongProtocolAssignment test использовал INVALID OrderedWholeBurst для protocol5 и не покрывал valid permutation; он сохраняется с прежним смыслом.

B1 Prepare/Commit остаётся private uninterrupted-frame примитивом, не deferred lease. Public Complete непосредственно вызывает Prepare→Commit без callback. Prepare заканчивается свежим CheckClock, который проверяет owner/control/Need/actual clock/budget; Commit noexcept сам stale state не валидирует. Будущий Service обязан завершить allocating staging до последнего Prepare/fresh check и commit без intervening callback/edit/Reset. При разрыве frame подготовку надо повторить. Такой service fault-control и runtime atomicity ещё не реализованы/не утверждаются этим исправлением.

Локально выполнены только Git/text/inventory metadata checks. C++ compilation, numerical tests, fake clocks, source snapshots для подмены execution evidence и server updates не выполнялись.
