# Передача владения декодированным архивом

У `DecodedNativeCompositeArchive` явно объявлен copy constructor. Без явных
move constructor/assignment передача через `std::move` копирует векторы
записей и первичных отсчётов в portable proof и фабриках импорта.

Кандидат исправления добавляет defaulted copy assignment и обе move операции.
Copy API сохраняется. Спецификация исключений определяется членами класса:
безусловный `noexcept` не добавляется. Схема архива, проверки доказательств,
математическая цель, физика и lifecycle компонентов не меняются.

Данные из сохранённого legacy proof не извлекаются разрушительно: сервис
сохраняет этот proof для последующего использования. Его отдельная копия
записей пока остаётся. Это изменение устраняет только непреднамеренные копии
при передаче владения; оно не гарантирует устранение всех причин OOM.

Адресная проверка в корневом SDK:
`NativeArchiveOwnership.MoveRetainsDecodedPrimaryStorageAndCopyIsIndependent`.
Она декодирует реальный сохранённый package6, проверяет адреса backing storage
записей и вложенных samples после move construction/assignment, независимость
явной копии и сохранность document/protocol/group/attempt идентификаторов.

На момент подготовки исправления серверная сборка и эта проверка ещё не
выполнены. Требуются проверка на сервере, isolated C0 при прежнем лимите 4 GiB,
сравнение peak memory и полный затронутый package regression. Предыдущие OOM
и Windows PASS не переоцениваются задним числом.
