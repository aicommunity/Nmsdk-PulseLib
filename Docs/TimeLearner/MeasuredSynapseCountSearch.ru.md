# Предложение числа синапсов по измерениям

Подготовлено для контроллера2 в отдельной ветке
`codex/timelearner-measured-count-search`. Работающие эксперименты используют
прежний PulseLib1c8d0112. Новая реализация прошла серверную сборку и146/146
проверок решающего контура на Windows, включая10 новых, без ошибок и
пропусков. Проверен commit649179dd978ef2f579b0c8c020f49643b0fccd3f.
Нативные пробы физической модели и сопоставимое обучение ещё предстоят;
реализация пока не является рекомендуемым алгоритмом.

Основание: в остановленной Branch-попытке с M=4 при24 новых кандидатах на
вход проверены Nₛ только до5–6 из разрешённых128. Совместного выполнения
временного и амплитудного допусков нет. Увеличение бюджета не доказывает
исправление порядка поиска; сначала требуется сопоставимый вариант.

`MeasuredSynapseCountSearch` предлагает целое число по двум или нескольким
проверенным точкам одной геометрии. При противоположных знаках ошибки
предпочитается внутренний кандидат измеренного интервала. Без такого
интервала разрешена ограниченная секущая как гипотеза следующего измерения.
Ранжирование интервалов использует фактическое расстояние до цели, затем
размер интервала и меньшую нижнюю границу. Глобальная монотонность и
достижимость цели из прогноза не следуют.

Повторы с разбросом выше амплитудного допуска, немонотонные данные,
невалидное время, NaN/Inf, вырожденный наклон и уже проверенное число
сохраняют обычный ограниченный просмотр. Соседние целые числа с ошибками
разных знаков не становятся Exact без измеренного попадания в допуск.

Контроллер сравнивает весь вектор параметров и поправки C. Известная
несогласованность повторов запрещает подбор секущей для этого контекста.
Если штатная подготовка Branch-кандидата меняет другие точки подключения,
прогноз для прежней геометрии не используется; соседний просмотр остаётся.

Предложения расходуют прежний локальный запас и общие бюджеты. Более
плохое измерение может создать полезный интервал со сменой знака, но не
пополняет запас. После изменения снова нужны нативные опорная и активная
пробы; финальная проверка всех входов остаётся независимой. CapturedPerInput,
допуски, N1, legacy-контроллер и lifecycle Rdk не изменяются.

Проверки арифметики и производственного контроллера включили превышение
цели, неустойчивые повторы и отрицательный финальный проход. Это контролируемые
наблюдения, без реального дерева Rdk. Далее нужны нативные Classic/Branch
проверки и сопоставимое обучение с прежним бюджетом. Синтетические
наблюдения решающего контура не подтверждают физическую сходимость.
