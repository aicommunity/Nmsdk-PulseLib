# Владение состоянием поиска одного входа

## Область изменения

`BoundedTrainingSession::InputSearchState` объединяет уже существовавшие поля
локального поиска. Это механическое выделение состояния, предшествующее
изменению порядка обхода входов. Математическая цель, параметры, бюджеты,
схемы архивов и публичный интерфейс контроллера остаются прежними.

Текущая реализация завершает локальный поиск входа до `AdvanceInput()`:
Classic посещает обучаемые входы в возрастающем порядке, Branch — в обратном.
Один такой визит может потребовать нескольких пар измерений и изменений
структуры. Выделение `InputSearchState` само по себе не вводит циклического
чередования входов Classic.

## Границы владения

| Состояние | Владелец | Причина |
|---|---|---|
| Фоновая модель при начале локального поиска | `InputSearchState` | Относительно неё формируются текущие кандидаты |
| Счётчик локальных кандидатов и выбранный лучший кандидат | `InputSearchState` | Относятся к поиску одного входа на данном фоне |
| Курсоры L/Ns/Rs, контексты C и их очерёдность | `InputSearchState` | Описывают перечисление локальных кандидатов |
| Выданные совместные кандидаты и локальные измерения | `InputSearchState` | Используются при локальном ранжировании |
| Фактическая текущая модель, revision и epoch | `BoundedTrainingSession` | Любое физическое изменение относится ко всему графу |
| Бюджеты проб, изменений и невалидных наблюдений | `BoundedTrainingSession` | Не возобновляются при смене входа или C-контекста |
| Лимит N0-предложений длины на вход | Общая карта с ключом входа | Не возобновляется при новом sweep или C-контексте |
| Pending/armed-действие, anchor и защита от повторной выдачи | `BoundedTrainingSession` | Незавершённую пробу нельзя переносить между входами |
| История доказательств и последняя измеренная выбранная граница | `BoundedTrainingSession` | Должны оставаться доступны адаптеру после смены входа |
| Независимая финальная проверка всех входов | `FinalVerificationSession` | Локальный выбор кандидата не доказывает Exact |

## Ограничение будущего циклического обхода

Локальное состояние не является checkpoint физической модели. Если другой
вход изменил граф, сохранённые `fullParameters`, полная карта C, остатки,
bracket и ранги относятся к прежнему revision. Их нельзя применять как свежие
измерения новой модели. Сохранённый лучший кандидат может стать только
предложением: требуется применить разрешённые параметры текущего входа к
актуальному фону и выполнить новые anchor/input-измерения. Необходимо отдельно
сохранять индивидуальные поправки остальных путей и dormant C-пути.

Будущий вариант чередования должен иметь явный версионированный выбор режима,
сохранять воспроизводимость существующих конфигураций, общие ограничения
поиска и независимую финальную проверку. Здесь такой режим не реализован.

## Проверка

Статическая проверка обратной подстановкой квалификатора `inputSearch.`
восстанавливает исходный `.cpp` побайтно, кроме исправленного комментария о
порядке обхода. Она не заменяет компиляцию. До приёмки необходимы сборка полных
production translation units до/после, одинаковый полный набор decision-тестов
и проверка native-интеграции с пересобранными зависимостями. Действующие опыты
используют прежний неизменяемый runtime; результат этих опытов не является
проверкой данного выделения состояния.
