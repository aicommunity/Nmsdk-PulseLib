# Статус исследования структурных классификаторов

Дата сводки: 2026-09-28. Этот документ объединяет исходный план аудита классификаторов, последующую проверку `NNeuronTrainer`/`NNeuronLearner`, исследование числа синапсов и уточнённую гипотезу о фиксированном пороге LTZone.

## Краткий ответ о пороге

Есть экспериментальная поддержка того, что один и тот же порог может убрать повторные спайки у нескольких структур разной длины. Значение `0.009` дало один фронт у проверенных структур `NNeuronTrainer` и `NNeuronLearner`. В шести парных клонах классификатора общий для всех классов порог `0.0085` оставил не более одного фронта на окно при длинах выбранной ветви 3, 8 и 17 сегментов.

Это подтверждает гипотезу только в ограниченном смысле: **на проверенных структурах общий порог ограничивал кратность ответа**. Оно не доказывает существование универсального порога для любых моделей и не гарантирует, что каждый класс продолжит отвечать на собственный паттерн. На короткой ветви класса 2 максимум LTZone-потенциала на его целевом паттерне (`0.007754`) ниже максимума на паттерне класса 1 (`0.008624`); одно пороговое сравнение не может пропустить меньший максимум и одновременно отсечь больший. На короткой и средней ветвях также теряются некоторые правильные ответы. Значит, число спайков и правильность классификации нужно оценивать отдельно.

Отсутствие верхнего ограничения числа синапсов само по себе пока не признано дефектом алгоритма: оба тренера нормализуют амплитуду, а не считают выходные импульсы. При фиксированных длине и пороге рост числа связанных синапсов действительно изменил ответ от 0 к 1 и затем к 2 спайкам. Это структурный фактор, который порог может компенсировать в отдельных рабочих областях, но не основание вводить произвольный лимит.

## Что остаётся ограниченным или не подтверждено

- **Не доказан универсальный порог** для любых длин, числа/расположения синапсов, типов LTZone и входных паттернов. Значения `0.009` и `0.0085` являются контрольными точками для конкретных сохранённых структур.
- В опыте с длинами 3/8/17 общий порог обеспечил не более одного фронта, но изменённая короткая/средняя структура не сохранила правильную классификацию. Это не эквивалентно обучению заново под каждую длину.
- На сохранённых Iris-примерах все десять правильных классов хотя бы раз активировались, но ни одна строка не была однозначной: шесть ответов имели два бита, четыре — три. Поэтому работа классификатора как однозначного распознавателя не подтверждена.
- `NClassifier` после исправления связей на проверенных примерах выдал `111`, то есть остался неуверенным. Для `NPCAClassifier` проверен только заявленный однопаттерновый путь; у него нет многоклассовой оценки точности.
- Полный исторический Iris-протокол не повторён: текущий клон обучался на других трёх входах, чем выбранная историческая десятка. Архивные `relearning_1/2` повторены с одной валидной строкой ID 22, а не со всем исходным набором; сохранённые XML-цели повреждены.
- Для `NNeuronTrainer` в одном классификаторном subtree обнаружено расхождение `TrainingDendIndexes` и фактически созданных длин. Оно не отменяет успешные отдельные `TestTrain`/Iris прогоны, но требует отдельной проверки сериализованного subtree перед использованием его как эталона точной сходимости.
- В библиотеке зафиксирован дрейф параметров `NPulseSynapse` (`5f3f06d` и `0be546f`), но не выполнены параметрические replay-клоны с историческим стандартом. Архивные даты не позволяют точно сопоставить конкретный Iris-запуск с версией параметров.
- Поздние ответы при торможении наблюдались и тормозной сигнал подтверждён на входе синапса/канала. Однако на длинных дендритах вклад затухающего торможения, повторного входа и остаточного потенциала не разделён причинно во всех случаях.

## Дальнейшие действия по порядку

1. **Зафиксировать критерии порогового подбора.** Для каждого входного окна считать число восходящих фронтов отдельно от битового ответа. Для чистых классов требовать один фронт правильного класса и ноль у проигравших; midpoint может быть неуверенным. Для одиночного нейрона отдельно проверять кратность при наличии отклика.
2. **Проверить общий порог на обученных структурах**, а не только на вручную изменённых длинах ветви: взять несколько завершённых Trainer/Learner моделей `NSPNeuron + NPulseLTZoneThreshold` с разными векторами длин, одинаковыми входными паттернами и фиксированными синапсами. Выполнить общую сетку порогов для всех структур и найти пересечение диапазонов «ровно один спайк». Физические параметры и число синапсов зафиксировать.
3. **Повторить классификационные replay при выбранном общем пороге**: чистые синтетические прототипы и midpoint для `NSpikeClassifier`; контроль агрегации нескольких примеров для `NClassifier`; затем десять Iris-строк. On/Off сравнивать парно. Если общий порог снимает пачки, но стирает правильные ответы, документировать предел одного порога; не исправлять его `argmax`.
4. **Разобрать оставшуюся сходимость `NNeuronTrainer`.** Сверить сериализованные векторы длины, фактические ветви и обучающие индексы на конкретном subtree, где найдена разница, и только после воспроизведения исправлять код.
5. **Сделать исторический параметрический replay только при необходимости.** Сравнить архивный стандарт с текущим на одном и том же клоне; ограничить изменение параметрами тестового клона. Не менять общие образцы `NPulseLibrary` и не оптимизировать физические параметры обучением.
6. **После пороговой калибровки повторно оценить классификаторы** на Iris и синтетических паттернах. В случае многобитного результата сохранять состояние «неуверенно»; не вводить выбор победителя через `argmax`.
