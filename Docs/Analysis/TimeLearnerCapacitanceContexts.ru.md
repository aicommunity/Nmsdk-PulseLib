# Совместные кандидаты L/Ns/Rs/C: конечные чередующиеся контексты

Статус: отдельная экспериментальная ветка, серверная проверка ожидается.
Это реализация decision controller, не приёмка native C-trim или этапа7.
Новая optional CapacitanceSearchPolicy отсутствует по умолчанию. Legacy
контроллер и старые конфигурации продолжают выбирать прежнее поведение.

При включённой policy BeginInput фиксирует background L/Ns/Rs и полный C-state.
Создаются контекст неизменённого состояния и конечная сетка абсолютных C/C0:
единица, границы и явно ограниченные dyadic subdivisions. Каждый контекст имеет
собственные очереди L/Ns/Rs, измеренные предложения и историю domain/candidates.
После полного измерения кандидата или отклонённого edit управление переходит
следующему контексту. N0 repeats завершаются целиком до перехода. Отказы N1-domain
также уступают очередь другому C. Бюджеты проб, edits, candidates и sweeps общие;
невыполнимость по исчерпанию не утверждается. Варианты C не исчерпывают по очереди
весь Ns/Rs mesh и не сбрасывают историю/опорные амплитуды новой сессией.

Для каждой фактической геометрии область берётся через CapacitanceRegion:
Classic [1,L_i], Branch (L_(i+1),L_i], last anchor неизменяем. Запрос строится
от полного background, восстанавливая также dormant поправки и новые unit paths.
Семантически одинаковые L/Ns/Rs/C кандидаты между контекстами не дублируются.
Пустая область при совпадающих Branch attachments не меняет общий кабель.

Новый C-контекст N1 не использует shortcut измерения текущего безопасного графа:
перед его поиском запрашивается свой совместный native domain для L/Ns/Rs/C.
Любой live edit инвалидирует domainReady всех сохранённых контекстов. Каждая
проба имеет свежий anchor того же revision; финальная all-input проверка
существующего контроллера остаётся обязательной и после локального совпадения.
Best candidate хранит полный C-state. Restore не наследует поздние поправки.

Перед reference probes native Start требует recorded C0 history и все три
capacitance capabilities, проверяет совместимость search/owned диапазонов.
Политика проверяет finite положительные границы, наличие C0, число контекстов,
общий candidate budget и худший допустимый размер области до её разворачивания.
Захват новых C0 и проверка численной устойчивости принадлежат native editor,
а не чистому контроллеру. Функции Build/Reset/Calculate здесь не вызываются.

Ограничения промежуточной реализации:
- measured C interpolation пока не интегрирована; используется конечная сетка
  и свежие измерения, без предположения монотонности;
- direct API policy пока не сериализуется в старые schemas1–3: cold Encode
  и learned/stopped export явно отказывают вместо тихой потери policy;
- diagnostic summary policy получает schema4 и явный enumeration contract;
  новые production readers/configuration/model codecs обязательны до приёмки;
- нужны normal/ASan real-component C-search, численная проверка, roundtrip,
  режимная/физическая матрица и визуальные отчёты всех паттернов.

Root tests CapacitanceContexts (10) используют настоящий decision controller
и recorder с управляемым тестовым откликом. Они проверяют fairness N0, полный
state/anchor/dormant, per-C N1 domains и их подмену, N0 repeats, положительный
Exact только после all-input проверки, повреждение Branch anchor и остановки.
Эти тестовые сигналы не являются физиологическим экспериментом.
