# Телеметрия в физическом model archive

## Уточнение28.11.2026: нейтральный буфер в определении образа

В новой Linux-проверке девяти реальных сценариев8 прошли, а повторный
archive roundtrip при20000 Гц дал различие определений двух образов
`NPMembraneBio`: неподключённый`InputFeedbackSignal` имел форму1×1 с нулём
до импорта и0×0 после него. В трёх циклах параметры, полный граф и
проверенные массивы входа, времени, канала и сомы совпали. Это ограниченное
наблюдение, а не доказательство эквивалентности любых динамических состояний.

Кандидат исправления канонизирует только приватную XML-копию определения
нативного`NPMembraneBio`: матрицу double ровно1×1 с конечным нулём,
без входящей или исходящей связи этого свойства, записывает как0×0.
Штатный потребитель суммирует элементы: оба представления дают нулевой
вклад. Ненулевой буфер, иная размерность, неизвестный тип, подключённое
свойство, другой native class и State самого экспортируемого графа не
изменяются. Общие Reset/Copy/Load, живой экземпляр и prototype не правятся.

Полное сравнение portable model archive принимает обе подписанные формы
только внутри определений таких образов, после проверки исходных hashes.
Старые документы не переписываются. Новые определения используют пустой
буфер. Остальные поля и связи сравниваются прежним способом.

Следующая серверная проверка12 сценариев дала11 успехов и один отказ
`RepeatedArchiveAndPoolReuseAt20000`. Буфер уже совпал; оставшееся различие
в двух определениях — запись пустых `TrainerClassName` как `<.../>` либо
`<...></...>`. Разбор обоих XML дал одинаковые узлы, атрибуты и значения.
Причина: путь Load/Save выполнялся только для исходной формы1×1, а для
уже пустой0×0 возвращались прежние байты. Исходный JUnit и полные архивы
сохранены во внешнем комплекте `Jump12-private-image-native12-fr764`.

Следующий кандидат проводит через один Load/Save обе строго проверенные
нейтральные формы. Это не изменение XML-сериализатора Rdk или State графа;
другие состояния по-прежнему не канонизируются. Побайтовое равенство
полного нового архива остаётся обязательной проверкой и не заменяется
семантическим сравнением в тесте.

Серверная приёмка этого уточнения ещё требуется: повторные native roundtrip
при2000/20000 Гц, старые archive controls и новые отрицательные проверки
ненулевого/более широкого буфера и отличий State живого графа. Сведения ниже
описывают прежнее изменение StepDuration и его собственную приёмку.

Реализация требует серверной приёмки; это не новый checkpoint динамики.
`ModelArchive::Snapshot` после штатного SaveComponent меняет только текст
`State/StepDuration` на `0` в приватном USerStorageXML. Обход следует реальному
дереву компонентов и соответствующим узлам `Components`; проверяются тип
свойства ptPubSysState, скалярная форма и полнота структуры. Поиск всех XML
элементов с похожим именем не используется. Живые объекты не изменяются.

StepDuration — явно разрешённая измеренная wall-time телеметрия UContainer.
Остальные State сохраняются: в них находятся необходимые связи. TimeStep,
MaxCalculationDuration, CalculationDurationThreshold и прочие параметры
сохраняются. Семантическая model identity и формат archive остаются прежними.
Прежние signed snapshots с ненулевым StepDuration читаются существующим
импортом с проверкой их исходных hashes, без переписывания истории.

Проверки в корне: native-archive-telemetry-v1.json. Нужны сравнение всего
snapshot живого графа до/после изменения counters, неизменность живых counters,
сохранение scheduler limits, отличие модели при изменении действующего
MaxCalculationDuration, импорт прежнего ненулевого counter и fresh-process
перенос несимметричной модели с точными matrix/physics, внешним источником,
полными input/channel/soma/time массивами при 2000 и 20000 Гц. Дополнительно
повторяются текущие отрицательные archive controls и learned C₀ transfer.

Полный signed archive может различаться transient buffers отдельных image
instances: в normal A1 обнаружен InputFeedbackSignal 0×0 → 1×1. Storage
сравнивается по полному semantic fingerprint. После native Load/Init меняется
также производная TimeConstant индивидуального канала; сохранять её старое
кэшированное значение не требуется от physical import. Параметры, граф и
реальный отклик должны сохраняться. Эти различия не удаляются из архивов
настоящим изменением; canonical StepDuration — только один разрешённый metric.

Это уменьшает одну подтверждённую причину нестабильных байтов. Другие различия
исторических больших PostTune пакетов требуют отдельного анализа. Уникальные
первичные результаты не удаляются, hashes старых пакетов не пересчитываются.
