# Индекс мембран после построения нейрона

`NPulseNeuronCommon::Membranes` — индекс непосредственных дочерних мембран.
После завершения native Build он следует их порядку в именованной таблице детей.
`NPulseNeuron::GetMembrane(i)` обращается к этому индексу.

Раньше AAddComponent только дописывал элементы в конец. UpdateComputationOrder
затем переставлял таблицу детей, оставляя индекс в порядке создания. Native XML
сохранял таблицу детей, и при загрузке индекс создавался уже в другом порядке.
В результате fresh и loaded графы имели одинаковую физику и вычислительный
порядок, но различались по индексированному доступу GetMembrane.

Теперь NPulseNeuronCommon::UpdateComputationOrder завершает обычный native hook
вызовом RefreshMembraneIndex; NPulseNeuron делает это после своего упорядочения,
включая режим 0, где сохранённый порядок детей остаётся неизменным. Никаких
дополнительных Calculate, Reset или перестановок scheduler не добавлено.

При промежуточных Add/Del список обновляется обычными hooks. Контракт о конечном
порядке относится к завершённому Build. Изменение структуры между пробами должно
завершаться штатным построением до нового измерения. Числовой индекс мембраны
нельзя сохранять как постоянный идентификатор при росте структуры: для обученного
состояния используются именованные пути.

Подтверждение выполняется native тестом асимметричного profile/XML roundtrip и
полным semantic model comparison, включая реальные cached pointers. Это не
checkpoint динамики и не подтверждение качества обучения.
