# Полные типы XML и целочисленные значения модели

Кандидат27.11.2026 расширяет проверку сравнения архивов, не меняя
управление learner, штатные методы Rdk или научную цель обучения.

`ModelIdentity` уже описывает целочисленные параметры как точные
`signed_integer`/`unsigned_integer`, независимо от номинального C++
типа. `SamePortableSnapshot` использует этот существующий контракт
только для соответствующих скалярных параметров. Полные пути XML
строятся по фактическому `child_order`, без разбора имён по точке и
без списка специальных параметров learner. Для остальных узлов
сохраняется номинальное сравнение типов Rdk.

Перед загрузкой CheckSnapshot проверяет соответствие скалярного
объявления Type логическому виду параметра; целое число должно точно
совпасть со значением identity. Подмена double на int не становится
допустимой после пересчёта SHA даже в DATA1. Штатная загрузка и полный
типизированный readback остаются обязательными: XML Type сам по себе
не доказывает реальный тип, граф или отклик восстановленного объекта.

Сравнение старых GCC/MSVC-обозначений контейнеров выполняет общий
Rdk-компонент. Значения, размерности, классы, связи, исходные digests,
метаданные происхождения и границы DATA1/2/3 не исключаются. Неизвестные
типы не получают значения известного типа. Разрядность legacy long
не угадывается: при разных номинальных целых типах допускается только
общий гарантированный диапазон. Архивы с большими неоднозначными
значениями должны получить отказ, а не успешный перенос по предположению.

Статус: реализация и расширенные интеграционные fixtures подготовлены;
новая серверная проверка ещё не выполнена. Прежние10+23 проверки
скалярного кандидата не заменяют проверку этой версии и полный прямой
импорт реальных DATA2/DATA3 с сохранением всех реакций. Научный
сертификат при переносе данных не возникает. Кандидат не принят в develop.
