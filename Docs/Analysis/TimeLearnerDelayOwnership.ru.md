# Пауза DatasetMatrix: кандидат свойства и владелец

24.11.2026. Общий контракт для `NNeuronTimeLearner` и
`NNeuronTimeLearnerBranch`. Изменение находится в отдельной ветке;
проверка исправленного кода на реальных компонентах ещё не завершена.

## Применение нового значения

Rdk вызывает setter до записи переданного значения в свойство.
Следовательно, `SetDelay(value)` должен вычислять эффективную паузу
по `value`; чтение `Delay.GetData()` в этом месте возвращает прежнее
значение. Собственное повторное присваивание свойства не требуется.

Пусть `p = SettleMarginSec() + kGapSlack`. Сохраняется прежнее правило:

```text
if AutoScaleIterationGap:
    effective = max(p, 1.55 seconds)
else:
    configured = requested > 0 ? requested : 0.5 seconds
    effective = max(configured, p, 1.55 seconds)
```

Граница1,55с уже существовала и обеспечивает нынешнее полное окно анализа
позднего ответа. Она не объявляется универсальной для всех физических
профилей. Новое изменение не сокращает эту границу и не меняет правила
подбора длины, амплитуды, сопротивления или порога.

NaN и обе бесконечности отклоняются до изменения свойств. При ручной
паузе переход3→5с должен сразу менять дочернюю паузу на5с; запрос0,2с
сохраняется как запрос, но эффективная пауза контрольной модели остаётся
1,55с. Нулевой и отрицательный запросы сохраняют прежний fallback0,5с
перед применением физической границы. Автоматический режим сохраняет
запрошенное значение, продолжая использовать вычисленную паузу.

## Владение и связанные свойства

При native-владении моделью, установленном recognition-состоянии или
занятом самостоятельном измерителе разрешается только присваивание
прежнего `Delay`. Оно не пишет в DatasetMatrix. Иное прямое присваивание
отклоняется штатным отказом setter Rdk. Reset learner сохраняет объявленную
модель и её владельца; Default освобождает native-владение штатным общим
путём `NativeLearnerLifecycle::BeforeDefault`.

Связанная дочерняя пауза принадлежит своему источнику. Setter не меняет
источник и не разрывает связь. Новый запрос допустим, если эффективная
пауза уже совпадает со значением источника; иначе присваивание отклоняется.
Собственное связанное свойство learner продолжает следовать семантике
Rdk: присваивание и обновление источника должны проверяться отдельно.
Эта адресная правка не создаёт новый обработчик связей на каждом тике.

`Build`, `Calculate` и `Reset` по-прежнему возвращают true. Отказ setter
использует существующий `EPropertySetterFail`; он не вводит передачу
ошибок через bool методов жизненного цикла. Дополнительных Build, Reset
или вложенных расчётных тиков здесь нет.

## Проверки и оставшаяся область

Исходный SDK PulseLib3f5a2205 проверен десятью реальными случаями:
восемь assertions не прошли, два автоматических режима прошли.
Исправленный файл тестов содержит18 случаев обеих топологий, включая
создание с заданной паузой, неположительный fallback, связанный дочерний
параметр и владение queued-пробой до первого импульса.

Исполнение этих18 случаев до/после, активная Running-проба, смена
частоты/размерности и общая lifecycle/storage-матрица ещё требуют
серверной приёмки. Компиляция или наличие тестов не означают её завершения.
